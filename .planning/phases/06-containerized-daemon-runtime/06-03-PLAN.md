# 06-03: Verify tdtool Communication Inside or Against the Container

## Objective

Create test script and documentation that verifies tdtool can communicate with the containerized daemon using the `docker exec` pattern.

## Context

Per 06-CONTEXT.md decisions D-06-04 through D-06-06, the primary communication method is `docker exec telldus tdtool <args>`. This is cleaner than bind-mounting Unix sockets to the host and is the recommended container-native approach. This plan creates the test infrastructure and documentation for this communication pattern.

**Key decisions to implement:**
- D-06-04: Use `docker exec` pattern as primary communication method
- D-06-05: This is the cleanest container-native approach
- D-06-06: Do NOT bind-mount Unix sockets to host for v1

- [ ] Test script verifies tdtool --list works via docker exec
- [ ] Test script verifies tdtool --help works via docker exec
