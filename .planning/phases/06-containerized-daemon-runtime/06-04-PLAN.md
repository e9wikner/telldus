# 06-04: Test Daemon/Container Restart Behavior

## Objective

Verify and document that container restart and daemon restart preserve configuration and runtime state without requiring device re-learning.

## Context

Per 06-CONTEXT.md decisions D-06-10 through D-06-13, the restart policy is `unless-stopped` for auto-recovery, USB disconnect/reconnect is handled by libftdi retries, state persistence is ensured by Phase 4, and config auto-reload is handled by inotify. This plan tests and documents these restart-safe behaviors.

**Key decisions to implement:**
- D-06-10: Use `restart: unless-stopped` policy for auto-recovery
- D-06-11: USB disconnect/reconnect handled by libftdi retries
- D-06-12: State persistence via Phase 4 volume/bind mount
- D-06-13: Config auto-reload via inotify (Phase 4)

- [ ] Test script includes restart behavior verification
- [ ] Documentation explains state persistence across restarts
- [ ] Documentation explains config auto-reload behavior
- [ ] Documentation explains USB disconnect recovery
