# 06-01: Define Docker Run Options for USB Passthrough and Service Permissions

## Objective

Create deployment artifacts (docker-compose.yml and helper script) that define the correct Docker run options for TellStick Duo USB passthrough using `--privileged` mode, state volume persistence, and restart policy.

## Context

Per 06-CONTEXT.md decisions D-06-01 through D-06-03, v1 uses `--privileged` mode for reliable USB passthrough. The Dockerfile from Phase 5 already includes tini as PID 1 and the entrypoint script. This plan creates the operational deployment configuration that operators will use.

**Key decisions to implement:**
- D-06-01: Use `--privileged` for USB passthrough (v1 pragmatic choice)
- D-06-10: Use `restart: unless-stopped` policy
- D-06-12: State persistence via volume for `/var/lib/telldus`

## Must-Haves

- [ ] docker-compose.yml exists with correct USB passthrough configuration
- [ ] scripts/run-telldus.sh helper script exists with documented run command
- [ ] Both artifacts include state volume for `/var/lib/telldus`
- [ ] Both artifacts use `unless-stopped` restart policy
- [ ] Both artifacts use `--privileged` flag

## Truths (Locked Decisions)

| ID | Decision | Implementation |
|----|----------|----------------|
| D-06-01 | Use `--privileged` mode for USB passthrough | docker-compose.yml and run script include `privileged: true` / `--privileged` |
| D-06-10 | Use `restart: unless-stopped` policy | Both artifacts specify `unless-stopped` restart behavior |
| D-06-12 | State persistence via volume | Both artifacts include `/var/lib/telldus` volume mount |
