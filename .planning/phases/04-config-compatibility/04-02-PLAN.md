<task type="auto">
  <name>Task 2: Add config auto-reload to daemon event loop</name>
  <files>telldus-core/service/SettingsConfuse.cpp, telldus-core/service/TelldusMain.cpp</files>
  <read_first>
    - telldus-core/service/TelldusMain.cpp (event loop structure, EventHandler usage)
    - telldus-core/service/Settings.h (class interface, existing methods)
    - .planning/phases/04-config-compatibility/04-CONTEXT.md (D-04-07, D-04-08)
    - .planning/phases/04-config-compatibility/04-RESEARCH.md (Pattern 3: debounced inotify)
  </read_first>
  <action>
    Implement debounced config auto-reload using inotify:
    1. In TelldusMain.cpp (or a new small helper class), initialize inotify:
       - Use inotify_init1(IN_CLOEXEC | IN_NONBLOCK)
       - Add a watch on the config file's parent directory for IN_CLOSE_WRITE | IN_MOVED_TO
       - Store the watch descriptor and file descriptor
    2. Add the inotify file descriptor to the TelldusMain event loop so it wakes the EventHandler when events arrive.
       - The event loop uses TelldusCore::Event and EventHandler; you may need to add a new Event type or use the existing data event mechanism.
       - Alternatively, if integrating inotify into the custom event system is complex, use a dedicated thread that reads inotify events and signals the main loop via an existing Event.
    3. When an inotify event fires for the config file name (e.g., "tellstick.conf"):
       - Set a debounce flag and start/restart a short timer (500ms).
       - When the timer expires without further events, call a new Settings::reloadConfig() method.
    4. Add Settings::reloadConfig() to Settings.h and SettingsConfuse.cpp:
       - Lock the mutex.
       - Free the existing cfg (d->cfg) if non-null.
       - Call readConfig(&d->cfg) with the resolved path.
       - Log a warning if re-read fails; do not crash.
       - The var config (d->var_cfg) must NOT be reloaded per D-04-08.
    5. Do NOT watch the var config file.
    6. If inotify is unavailable at compile time (headers missing), guard the code with #ifdef __linux__ or #ifdef HAS_INOTIFY and make auto-reload a no-op on other platforms.
    7. Include <sys/inotify.h> where needed.
  </action>
  <acceptance_criteria>
    - TelldusMain.cpp or helper initializes inotify and watches the stable config directory
    - Settings class has a reloadConfig() method that re-parses the stable config
    - A debounce mechanism (timer or delay) prevents reload races during writes
    - Var config is not reloaded
    - Build compiles with zero new warnings on Linux
    - If inotify headers are missing, the build still succeeds (optional compilation guard)
  </acceptance_criteria>
  <verify>
    <automated>
      grep -q 'inotify_init1\|inotify_add_watch' telldus-core/service/*.cpp telldus-core/service/*.h && \
      grep -q 'reloadConfig' telldus-core/service/Settings.h telldus-core/service/SettingsConfuse.cpp && \
      grep -q 'readConfig' telldus-core/service/SettingsConfuse.cpp && \
      echo "PASS"
    </automated>
  </verify>
  <done>Debounced inotify-based config auto-reload is integrated into the daemon event loop.</done>
