# AGENTS.md — deploy/

Guidance for AI assistants working in this directory. The top-level
`AGENTS.md` is generated by GSD from `PROJECT.md`/`CONVENTIONS.md`/etc. and
covers the C++ codebase; this file covers `deploy/` only, which is neither
generated nor part of that codebase.

## What this directory is

The `hubbabubba` deployment: `telldusd` plus the `telldus-mqtt` bridge as a
rootless Podman quadlet, run from a checkout of this repo on that host. Read
`deploy/README.md` first.

It is **additive**. The Docker and native paths in the top-level `README.md`
are the general-purpose ones and must keep working — do not change
`Dockerfile`, `docker-compose.yml` or `scripts/` to suit this deployment.
Anything hubbabubba-specific belongs here.

## Rules

1. **No sudo, ever.** Everything `deploy.sh` writes is inside the deploying
   account's home or inside a directory the host granted that account
   ownership of. A change that needs root is a change to hubbabubba's host
   preparation (its `podman` role), not to this script. The whole point of
   the quadlet is that it replaces Docker's `--privileged` with a udev ACL
   and a user-namespace mapping.

2. **Never commit `deploy/deploy.env` or `deploy/tellstick.conf`.** Both are
   gitignored — the broker password and the household's house/unit codes, in
   a public fork. Neither has a copy in git, so overwriting or deleting one
   on a host is not recoverable by checking anything out. Reading them is
   fine. When a new value is needed, add it to the `.example` file with a
   comment on how to obtain it, and tell the user what to change by hand.

3. **A value goes in `deploy.env` only if it is hardware or site policy** — a
   password, a broker address, where appdata lives. Everything else (the user
   namespace mapping, the volume layout, the image name) is committed in
   `telldus.container.in`.

4. **Preflight checks name their fix.** Each `die` says what state is missing
   and the command or file that establishes it. A failure should read as a
   pointer to a skipped step, not a puzzle.

5. **Bash: `set -euo pipefail`; nothing beyond `podman` and coreutils.** In
   particular do not render the template with `sed` or `envsubst` — paths
   contain `/` and values can contain `&`, and both tools interpret those.
   `render()` explains why it is written the way it is.

6. **The comments in `telldus.container.in` are load-bearing.** Every
   non-obvious line there — the host network, `keep-id:uid=65534`, the
   bind-mounted `/dev/bus/usb` tree, the separate environment file — is there
   because the obvious alternative was tried and failed in a specific,
   documented way. Do not strip them; when you change the behaviour, update
   the reasoning.

## Verification

No tests, no CI. `bash -n deploy/deploy.sh`, `deploy/deploy.sh --help` (it
prints its own header by line range, so a header edit can silently break it),
and the checks in `deploy/README.md`.

One trap worth repeating: `tdtool --list` succeeding proves nothing about
device access — it only queries `telldusd`'s in-memory config over a local
socket. `tdtool --on` is what exercises the USB path, and it is what catches
a broken ACL or user-namespace mapping.
